나의 한 페이지

이 페이지는 잠재적인 협업자나 채용 담당자에게 비효율을 개선하고 주도적으로 문제를 해결하는 저의 실제 업무 스타일과 경험을 보여주기 위한 공간입니다.

말이 아닌 근거: 강점과 경험

1. 주어진 환경에 얽매이지 않는 효율성 추구

상황: 유지보수 업무 중 사용자가 입력하는 데이터에 이상한 문자열이 섞여 들어오는 경우가 잦았고, 팀원들은 기본 메모장만으로 이를 확인하느라 데이터 검증에 오랜 시간을 소모함.

행동: 비효율을 개선하기 위해 공통 툴 폴더를 탐색, 대용량 텍스트 처리와 패턴 검색에 유리한 Sublime Text를 직접 찾아 설치하고 업무에 적극 도입함.

결과: 비정상적인 문자열을 빠르고 정확하게 찾아내어 데이터 검증 시간을 단축하고 유지보수 업무 효율성을 크게 높임.

📂 근거 자료: 이상 데이터 검증용 정규식(Regex) 가이드 스니펫 (기업 식별 정보 제거됨)
// 사용자 입력 데이터 중 특수문자/이상 문자열 필터링 정규식
// Sublime Text 'Find' (Ctrl+F) -> Regex Mode(Alt+R) 활성화 후 사용

1. 비정상적인 유니코드 문자열 감지:
   [^\x00-\x7F가-힣ㄱ-ㅎㅏ-ㅣ]

2. 공백 문자가 연속으로 3번 이상 들어간 경우 (데이터 오염 의심):
   \s{3,}

* 메모장 대신 Sublime Text 적용 후, 50MB 이상 로그 파일에서
  이상 데이터 탐색 소요 시간 약 80% 단축 확인.

2. 반복되는 문제의 체계화

상황: 시스템 유지보수 중 반복 발생하는 데이터 오류 해결책이 구두로만 전달되어, 동일 문제 발생 시 대응이 지연됨.

행동: 자주 발생하는 이상 데이터 유형과 Sublime Text를 활용한 검증 방법을 마크다운(Markdown) 형태의 가이드 문서로 정리함.

결과: 문서화 이후 비슷한 이슈 발생 시 즉각적인 대응이 가능해져 팀 내 문제 해결 시간을 단축하는 관찰 가능한 성과를 냄.

3. 새로운 환경에 대한 빠른 실행력

상황: 나를 알릴 수 있는 개인 페이지를 빠르고 안정적으로 배포하여 외부에 공유해야 했음.

행동: 복잡한 서버 설정 대신, GitHub 레포지토리와 Vercel을 연동하는 프론트엔드 배포 워크플로우를 학습하고 환경을 직접 구성함.

결과: 코드가 푸시될 때마다 라이브 URL로 즉시 자동 배포되는 CI/CD 환경을 구축하여 현재 페이지를 성공적으로 퍼블리시함.

공개 범위 점검표

  • 주도적인 문제 접근 방식과 문서화 역량
  • 관심 있는 개발 분야와 현재 습득한 배포 환경(Vercel 연동) 구축 능력

  • 보안에 위배될 수 있는 실제 고객 데이터 및 내부 소스 코드 전체
  • 개인 전화번호, 상세 주소 등 민감한 개인정보 (연락처는 이메일로 한정)
